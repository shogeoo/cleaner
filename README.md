# DesktopPrank

Тестовая нативная программа Windows x64 на C++17. Релиз ещё не подтверждён проверкой в Windows. Нужны Windows 10/11, обычный Explorer и видимый значок Корзины. Запуск без прав администратора.

## Сборка в Arch Linux

```bash
./scripts/build.sh
```

Результат: `dist/DesktopPrank.exe`. Требуются MinGW-w64 GCC/G++, binutils и windres. Все записи уже преобразованы из предоставленных MP3 в PCM WAV и находятся в `assets/`; ffmpeg для повторной сборки не нужен. Программа использует штатные DLL Windows, включая UCRT; поставлять DLL, аудио, Python или .NET рядом с EXE не требуется. Файлы 12 и 14 не используются.

## Поведение

После явного подтверждения программа записывает пути и PIDL всех значков, их координаты и исходные настройки упорядочивания в `%LOCALAPPDATA%\DesktopPrank\recovery-*.prj`. Окна сворачиваются. Автоупорядочивание и привязка к сетке временно отключаются, чтобы значки не смещались между переносами. При обычном завершении настройки возвращаются.

Курсор движется по прямой: шаг по длине до 15 пикселей с учётом округления координат, задержка 25 мс. Левую кнопку программа действительно удерживает; Explorer начинает обычное перетаскивание значка. Поверх Корзины размещается практически невидимая область приёма OLE. Она проверяет, что перетаскивается ровно один ожидаемый объект, и выполняет `IFileOperation` с флагами переноса в Корзину. Это позволяет сохранить точный PIDL полученного объекта через `PostDeleteItem`. Цель сообщает Explorer, что перенос уже выполнен, чтобы источник не удалял файл повторно.

Переносятся непосредственные элементы личного рабочего стола на локальном фиксированном диске. Системные значки, общие элементы Public Desktop, сетевые диски, элементы с атрибутом SYSTEM и reparse points пропускаются. Папки переносятся целиком. Операция отменяется, если Shell не выставляет признак возможности переноса в Корзину. Подтверждение результата обязательно; при ошибке дальнейшая уборка прекращается и запускается восстановление.

Озвучка последовательная. Реплики 3 и 11 звучат максимум по одному разу; события вмешательства учитываются с интервалом не менее 6 секунд. Реплика 6 используется только при наличии подходящей папки «Новая папка». Реплика 10 — от 15 доступных для переноса элементов. Реплики, зависящие от нескольких успешных переносов, не звучат, если элементов недостаточно.

Обработчики ввода работают в отдельном потоке. `Ctrl+Shift+S+P` отменяет новые переносы, сразу разрешает ввод и останавливает аудио. Затем звучит 16, восстанавливаются только объекты с подтверждёнными переносами, возвращаются позиции, программа завершается. Операция, уже начатая Shell, может завершиться; её результат включается в восстановление. Через 180 секунд блокировки отдельный поток также прекращает блокировку и запрашивает остановку. Системный защищённый экран, Ctrl+Alt+Del и окна повышенного уровня привилегий эти hooks не блокируют.

## Восстановление после обычного завершения

В Windows:

```powershell
.\DesktopPrank.exe --restore
```

Выберите журнал из `%LOCALAPPDATA%\DesktopPrank`. Можно указать его явно:

```powershell
.\DesktopPrank.exe --restore "C:\Users\USER\AppData\Local\DesktopPrank\recovery-....prj"
```

Восстановление выполняется программно через Shell. Существующий файл по исходному пути не перезаписывается: конфликтующий объект остаётся в Корзине и в журнале для повторной попытки. При восстановлении временно отключается автоупорядочивание, затем возвращаются координаты и исходные флаги. Программа проверяет координаты после включения исходных настроек и сообщает о расхождениях. Сама Windows может перестроить сетку при включённом автоупорядочивании; это требует проверки на вашем компьютере.

Журнал не является резервной копией содержимого. Если пользователь очистил Корзину, восстановить объект этим способом нельзя. Принудительное завершение процесса или отключение питания между действием Shell и записью его результата оставляет небольшое окно, когда последний объект может требовать ручного восстановления. Журнал `.tmp` может содержать более свежий результат; не удаляйте его при таком сбое. Программа не очищает Корзину, не устанавливается и не создаёт автозапуск.

## Проверка в Windows

Порядок и таблица результатов: [WINDOWS_TEST.md](WINDOWS_TEST.md). Проверка ресурсов и записи/чтения журнала без доступа к рабочему столу:

```powershell
$p = Start-Process .\DesktopPrank.exe -ArgumentList '--self-test' -Wait -PassThru
$p.ExitCode
```

Код 0 означает успех внутренней проверки, 1 — ошибку. Это не проверка Explorer и переноса файлов.

## GitFlow

`main` содержит только начальную основу репозитория до подтверждения готового релиза. Реализация создаётся в `feature/desktop-cleanup` от `develop` и сливается в `develop`. После проверки Windows исправления пойдут через новые `feature/*`, а готовый релиз — через `release/*` в `main` и `develop`. Формат коммитов: `<type>(<scope>): <description>`.

API: [позиции значков](https://devblogs.microsoft.com/oldnewthing/20130318-00/?p=4933), [PreDeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem), [протокол оптимизированного перемещения OLE](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios).
